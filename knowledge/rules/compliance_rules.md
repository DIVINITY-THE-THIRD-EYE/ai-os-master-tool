# AI OS v4 Multi-Agent Compliance Rules (`compliance_rules.md`)

## 1. Governance & Regulatory Framework Alignment

AI OS v4 complies with major enterprise compliance and regulatory frameworks, including **SOC 2 Type II**, **GDPR**, **HIPAA**, **ISO/IEC 27001**, and the **EU Artificial Intelligence Act (EU AI Act)**. These rules govern automated processing, data privacy, user consent, audit retention, and system transparency.

---

## 2. Regulatory Compliance Rule Specifications

### Rule CMP-001: SOC 2 Type II Security & Confidentiality Controls
- **Rule ID**: `CMP-001`
- **Severity**: `CRITICAL`
- **Scope**: Platform Architecture & Operations
- **Description**: Systems must satisfy Trust Services Criteria (CC6.1-CC6.8). All system access, privilege changes, administrative actions, and configuration modifications must generate tamper-evident audit trails.

### Rule CMP-002: GDPR Data Minimization & Right-to-Erasure (RTBF)
- **Rule ID**: `CMP-002`
- **Severity**: `CRITICAL`
- **Scope**: User Data & Memory Systems
- **Description**: Personal data must be limited to the minimum necessary for task execution. Upon receipt of a valid Erasure Request (`EVT_CMP_GDPR_ERASE`), all persistent memory, vector indexes, and session caches associated with the specified data subject MUST be purged within 72 hours.
- **Verification Protocol**:
  ```python
  def execute_gdpr_erasure(subject_id: str) -> VerificationReport:
      purged_records = []
      purged_records.extend(memory_store.delete_subject_records(subject_id))
      purged_records.extend(vector_db.delete_embeddings_by_subject(subject_id))
      log_compliance_event(
          event_type="GDPR_ERASURE_COMPLETE",
          subject_id=hash_sha256(subject_id),  # Hash for audit proof without leaking identity
          record_count=len(purged_records),
      )
      return VerificationReport(status="SUCCESS", purged_count=len(purged_records))
  ```

### Rule CMP-003: HIPAA Health Information Privacy & Safeguards (PHI)
- **Rule ID**: `CMP-003`
- **Severity**: `CRITICAL`
- **Scope**: Healthcare Domain Workflows & Agent Contexts
- **Description**: Protected Health Information (PHI) must be encrypted in transit (TLS 1.3) and at rest (AES-256-GCM). Agents operating in healthcare contexts must enforce Business Associate Agreement (BAA) boundaries and strict access logs for any PHI attributes.

### Rule CMP-004: EU AI Act Transparency & Human Oversight (High-Risk AI)
- **Rule ID**: `CMP-004`
- **Severity**: `HIGH`
- **Scope**: Autonomous Decision Engine & High-Risk Agents
- **Description**: High-risk AI agent operations (e.g., automated hiring, credit scoring, legal evaluation) must comply with EU AI Act Article 14 (Human Oversight):
  - Provide human operators with real-time interpretation of decision outputs.
  - Maintain detailed technical documentation of prompt parameters and model weights.
  - Provide a manual override button to halt agent execution instantly.

### Rule CMP-005: ISO/IEC 27001 Information Security Management System (ISMS)
- **Rule ID**: `CMP-005`
- **Severity**: `HIGH`
- **Scope**: Entire Skill Package & Repository
- **Description**: Access to knowledge assets, prompt templates, and security rules is restricted according to the organization's ISMS classification policy. Artifacts are classified into `PUBLIC`, `INTERNAL`, `CONFIDENTIAL`, and `RESTRICTED`.

### Rule CMP-006: Data Sovereignty & Geographic Transfer Rules
- **Rule ID**: `CMP-006`
- **Severity**: `CRITICAL`
- **Scope**: Cross-Region Cloud Routing & LLM Endpoints
- **Description**: Tenant data designated with residency constraints (e.g., `EU_ONLY`, `US_GOV_CLOUD`) MUST NOT be transferred outside the designated geographic boundary or routed to non-compliant LLM inference regions.

### Rule CMP-007: Mandatory Automated Compliance Attestation
- **Rule ID**: `CMP-007`
- **Severity**: `HIGH`
- **Scope**: Compliance Checker Agent (A08)
- **Description**: Every major release candidate must receive a signed `ComplianceAttestationReport` generated by Agent A08 certifying zero active regulatory violations.

### Rule CMP-008: Immutable Audit Log Retention & Legal Hold
- **Rule ID**: `CMP-008`
- **Severity**: `HIGH`
- **Scope**: Audit Subsystem
- **Description**: Audit logs must be stored in Write-Once-Read-Many (WORM) storage. In the event of a `LEGAL_HOLD` flag, automated purge rules are suspended indefinitely for targeted records.

### Rule CMP-009: Data Breach Incident Notification SLA
- **Rule ID**: `CMP-009`
- **Severity**: `EMERGENCY`
- **Scope**: Security & Incident Response Agents (A07, A11)
- **Description**: Upon identification of a confirmed data spill or unauthorized exposure event, `A11` must issue an automated alert within 15 minutes to trigger the enterprise 72-hour regulatory notification workflow.

### Rule CMP-010: Third-Party AI Model & Vendor Compliance Audit
- **Rule ID**: `CMP-010`
- **Severity**: `MEDIUM`
- **Scope**: External LLM Provider Integration
- **Description**: External model APIs must be verified to ensure they guarantee zero data retention for fine-tuning or training purposes (`Zero Data Retention - ZDR` SLA verified).
