# AI OS v4 Multi-Agent Coding Rules (`coding_rules.md`)

## 1. Overview & General Standards

All code generated by agents (A04 Lead Engineer, A05 Code Implementer) or written by human contributors must adhere to strict production-grade software engineering standards. Code must be clean, deterministic, strictly typed, fully tested, and resilient to failure.

---

## 2. Coding Rule Specifications

### Rule COD-001: Strict Type Annotations Mandatory
- **Rule ID**: `COD-001`
- **Severity**: `CRITICAL`
- **Scope**: Python, TypeScript, Go
- **Description**: Implicit `any` in TypeScript or untyped function signatures in Python (`def foo(x):`) are prohibited. All variables, parameter lists, and return types must have explicit type declarations.
- **Python Compliant Example**:
  ```python
  from typing import List, Dict, Optional


  def process_agent_results(
      task_id: str, payloads: List[Dict[str, Any]], timeout_seconds: Optional[int] = 30
  ) -> Dict[str, Any]: ...
  ```

### Rule COD-002: Comprehensive Error Handling & Custom Exceptions
- **Rule ID**: `COD-002`
- **Severity**: `CRITICAL`
- **Scope**: All Executable Code
- **Description**: Catch-all `except Exception: pass` or bare `catch(e) {}` blocks are strictly forbidden. All exception handlers must capture specific error classes, log relevant context, and either rethrow or execute explicit recovery.
- **Exception Hierarchy Mandate**:
  ```
  AIOSBaseException
  ├── AgentExecutionException
  │   ├── AgentTimeoutException
  │   └── AgentCapabilityException
  ├── VerificationException
  └── PolicyViolationException
  ```

### Rule COD-003: Deterministic Concurrency & Async Control
- **Rule ID**: `COD-003`
- **Severity**: `HIGH`
- **Scope**: Parallel Workflows & Async Code
- **Description**: Asynchronous routines must use explicit timeouts (`asyncio.wait_for`, `Promise.race`) and signal cancellation handlers to prevent dangling background tasks or memory leaks.

### Rule COD-004: Data Immutability & Defensive Copying
- **Rule ID**: `COD-004`
- **Severity**: `HIGH`
- **Scope**: Shared State & Context Management
- **Description**: Functions operating on shared configuration, state dictionaries, or context objects MUST NOT mutate input parameters in-place. Use defensive copies or frozen data structures (e.g., `dataclass(frozen=True)` or `Readonly<T>`).

### Rule COD-005: Strict Boundary Input Validation
- **Rule ID**: `COD-005`
- **Severity**: `HIGH`
- **Scope**: All API Handlers & Function Call Barriers
- **Description**: Inputs received from untrusted callers, LLM outputs, or network endpoints must be validated against a Pydantic model (Python) or Zod schema (TypeScript) before processing.
- **Python Pydantic Example**:
  ```python
  from pydantic import BaseModel, Field, SecretStr


  class AgentTaskRequest(BaseModel):
      task_id: str = Field(..., regex=r"^TSK-\d{3,6}$")
      agent_id: str = Field(..., regex=r"^A\d{2}$")
      priority: int = Field(default=2, ge=0, le=4)
      payload: Dict[str, Any]
  ```

### Rule COD-006: Automated Linting & Static Analysis Compliance
- **Rule ID**: `COD-006`
- **Severity**: `HIGH`
- **Scope**: CI/CD Verification Gate
- **Description**: All committed code must pass static analysis checks with zero warnings or errors:
  - Python: `flake8`, `mypy --strict`, `black --check`, `ruff`
  - TypeScript: `eslint --max-warnings 0`, `tsc --noImplicitAny`

### Rule COD-007: Mandatory Test Coverage Standard
- **Rule ID**: `COD-007`
- **Severity**: `HIGH`
- **Scope**: Unit & Integration Test Suites
- **Description**: Code changes must include co-located unit tests. Total statement coverage for new or modified modules must be $\ge 85\%$, with $100\%$ branch coverage for critical security paths.

### Rule COD-008: Structured Logging Standard
- **Rule ID**: `COD-008`
- **Severity**: `MEDIUM`
- **Scope**: Application Logging
- **Description**: Standard `print()` statements are prohibited in production code. All output must use structured JSON loggers (`structlog` or `winston`) with mandatory keys (`timestamp`, `level`, `module`, `task_id`, `trace_id`).

### Rule COD-009: Resource Lifecycle Management & Resource Leaks
- **Rule ID**: `COD-009`
- **Severity**: `HIGH`
- **Scope**: I/O Operations, Network Sockets, File Handles
- **Description**: File handles, network connections, database pools, and subprocesses must be managed via context managers (`with` statements in Python, `try/finally` in TypeScript) to guarantee release upon exit.

### Rule COD-010: Explicit Deprecation Tagging
- **Rule ID**: `COD-010`
- **Severity**: `LOW`
- **Scope**: Code Refactoring
- **Description**: Deprecated functions or classes must be decorated with `@deprecated(since="v4.1.0", removal="v4.3.0")` and emit runtime warnings.
